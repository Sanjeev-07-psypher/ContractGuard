# Design decisions

Choices not fixed by the HLD, recorded as required by HLD §0. Newest last.

| # | Date | Phase | Decision | Reason |
|---|---|---|---|---|
| D1 | 2026-10-22 | 0 | Packaging via `pyproject.toml` (setuptools) with extras `training`, `app`, `ollama`, `dev` instead of two requirements files. | One file; the core install stays free of FastAPI/Streamlit, matching HLD §0.2. |
| D2 | 2026-10-22 | 0 | Env overrides: `CG_` prefix with `__` nesting (e.g. `CG_LLM__RPM=4`), plus the flat names `LLM_PROVIDER`, `LLM_MODEL`, `GEMINI_API_KEY` from `.env.example`. Precedence: env > `.env` > `settings.yaml`. | Lets the Windows Tesseract path and model name be set without editing YAML. |
| D3 | 2026-10-22 | 0 | `llm.model` added to `settings.yaml` (default `null`, set via `LLM_MODEL`); `llm.provider` may also be `none`. `paths` section added for data/uploads/sqlite/models. `policy.policies_dir` added. | HLD §9.1 forbids hard-coding the model; paths must not be hard-coded either (§0.4). |
| D4 | 2026-10-22 | 0 | Use `import pymupdf` (not `fitz`). | PyMuPDF ≥ 1.24 deprecates the `fitz` alias. |
| D5 | 2026-10-22 | 0 | Tooling targets Python 3.11 (`requires-python >= 3.11`, ruff `py311`). | HLD §0.6. |
| D6 | 2026-10-22 | 1 | Gold contracts are authored once as YAML (`evaluation/gold/src/*.yaml`) and `build_gold.py` generates the DOCX, the text PDF (LibreOffice headless export of the DOCX) and the scanned PDF (rendered at 200 DPI, seeded skew/noise/blur, image-only), plus `gold.json`. | Single source of truth; all 24 files are reproducible. |
| D7 | 2026-10-22 | 1 | GC03 uses real Word auto-numbering (`w:numPr`) for its clause numbers; the other seven type numbers as text. | Exercises the DOCX numbering synthesis of HLD §6.1 on at least one gold file. |
| D8 | 2026-10-22 | 1 | DOCX files carry a running header and a "Page X of Y" footer. | The exported PDFs then exercise header/footer and page-number removal (HLD §6.2). |
| D9 | 2026-10-25 | 1 | Gold expiry dates use the legal reading: a term of N years from date D ends the day before the Nth anniversary (1 Apr 2026 + 1 year → 31 Mar 2027). The HLD's "effective date + duration in days" is an implementation shortcut; Phase 5 must match the legal reading. | Sanjeev asked for the best option (2026-10-25); a reviewer expects the legal date. |
| D10 | 2026-10-25 | 1 | GC06 and GC07 render to 2 pages, so header/footer removal (needs ≥ 3 pages, HLD §6.2) is skipped for them. Kept as is. | Exercises the short-document branch; their running header stays in the text. |
| D11 | 2026-10-25 | 1 | Gold labels drafted by Claude are "labeller 0". Sanjeev is labeller 1; labeller 2 is still to be named. | HLD §12.2 requires two independent human labellers. |
| D12 | 2026-10-25 | 2 | `Block` gains an optional `style` field (DOCX paragraph style); new stage models `TextSpan` and `CleanedText` carry the cleaned text and its offset map. | HLD §6.1 keeps `Heading*` styles as segmentation hints and §6.2 requires the offset map, but §5 has no field for either. Additive, optional fields only. |
| D13 | 2026-10-25 | 2 | Cleaning adds one rule to HLD §6.2 step 4: a line holding only a clause number ("10.1") is joined with the next line. Pattern `cleaning.number_only_line`. | LibreOffice-exported PDFs of Word auto-numbered lists put the number on its own line; without the join, segmentation would miss sub-clauses. |
| D14 | 2026-10-25 | 2 | Tesseract missing → scanned pages raise `OCR_UNAVAILABLE` for the whole PDF (no partial report). | HLD §6.1: "scanned PDFs return a clear error". |
| D15 | 2026-10-25 | 2 | Known limitation of the HLD header/footer rule: on very short pages every line sits in the top/bottom zone, so body lines that differ only in digits can be dropped as "repeating". Kept as specified; real headers are the target. | Found by a unit test; documented rather than diverging from the HLD. |
| D16 | 2026-10-25 | 2 | The scanned gold PDFs are simulated (render + skew + blur + noise), so the measured OCR CER (1.1% mean) is likely optimistic versus real print-and-scan. A real scan of at least one contract is recommended before the final report. | Honest reporting of E3. |
| D17 | 2026-10-25 | 3 | OCR-tolerant roman numerals: after `ARTICLE`, the characters `l`, `1`, `i` and `|` are read as `I` ("ARTICLE Ill" → III, "ARTICLE |" → I, "ARTICLE Vil" → VII). | Tesseract misread every roman I in the GC07 scan; without this, ARTICLE I and VII were lost. |
| D18 | 2026-10-25 | 3 | A clause-start line has a heading only if it is all caps, or ≤ 12 words, does not end in `.`/`;`/`,`, and ≥ 60% of its content words are capitalised. All-caps headings are shown in title case. | The HLD's "short line" test took wrapped sentences ("10.3 On termination, the Contractor shall withdraw its") as headings. |
| D19 | 2026-10-25 | 3 | A short clause merged into the next keeps the next clause's number and takes the short clause's heading ("3. TERM" + "3.1 ..." → number 3.1, heading Term, path `3 > 3.1`). | Matches how the gold set records sub-clauses and keeps the parent heading visible. |
| D20 | 2026-10-25 | 3 | Segmentation is scored by matching each gold clause's first eight words to a predicted clause's opening text (rapidfuzz partial ratio ≥ 85, one to one, in order, look-ahead 3), micro-averaged. | Robust to OCR slips; offsets differ across formats so character-exact boundaries cannot be compared. |
| D21 | 2026-10-25 | 3 | The segmentation score (F1 0.986–1.000) is optimistic: the gold contracts were generated with clean, regular numbering, and the labels are still a draft. The HLD asks for 10 contracts; the 2 CUAD contracts are pending Hugging Face access. The only misses are the GC06/GC07 PDF preambles, where the running header left by D10 precedes the title. | Honest reporting of E2. |
| D22 | 2026-10-25 | 5 | Termination notice: a duration introduced by "within" is skipped (it is a cure period, as in "fails to cure within 30 days of notice"). Otherwise HLD 7.3 as written: 12-token window to "notice", convenience sentences preferred, minimum taken. | Without it, GC08 returned the 30-day non-payment cure period instead of the 60-day notice. |
| D23 | 2026-10-25 | 5 | Header/footer removal (Phase 2) now counts top-zone and bottom-zone repeats separately. | A sentence wrapping across a page break ("fifteen" / "(15) days' notice" at the foot of page 2, "(30) days' notice" at the head of page 3) was being deleted as a running header in GC04's PDFs. Found by the Phase 5 evaluation. |
| D24 | 2026-10-25 | 5 | Soft-wrap joining also joins a line that starts with "(15) days"-style text (a parenthesised number then a lowercase word) to the previous line. | "fifteen\n(15) days' notice" was split, so the notice sentence lost its duration. List items such as "(1) The Vendor" start uppercase and are not joined. |
| D25 | 2026-10-25 | 5 | Fact evidence is the whole sentence that matched (a verbatim substring of the clause), not only the matched span. Conflicting values give `ambiguous=True` with value None (except termination notice: minimum). Facts whose category has no clause are None with no evidence. | Phase 7 explanations must quote evidence; Phase 6 then sends ambiguous facts to NEEDS_REVIEW. |
| D26 | 2026-10-25 | 5 | `counterparty_unilateral`: False if any notice sentence is mutual or gives the right to our organization; True only if every convenience right belongs to the counterparty; None when roles are unknown or there is no convenience wording. | HLD 7.3 gives the idea; this fixes the edge cases (both parties with separate rights, as in GC04). |
| D27 | 2026-10-25 | 5 | Sentences: spaCy sentencizer plus a merge after abbreviations listed in `patterns.yaml` (`Pvt.`, `Ltd.`, `Rs.`, ...). The spaCy EntityRuler for money and durations (HLD 7.1) is not built: no V1 fact uses money entities, and durations are matched by `durations.py`. `en_core_web_sm` is used only for the ORG fallback for parties. | Keep only what a fact needs; documented as a deliberate gap. |
| D28 | 2026-10-25 | 5 | `extraction/document.py` (not in the HLD layout) assembles `ContractMeta`. The expiry date is computed only when the term sentence mentions the Effective Date (GC08's "12 months from delivery" gives None, as in gold). | One place for document-level fields. |
| D29 | 2026-10-25 | 5 | E4 is measured with gold clause categories (no classifier yet): 100% on all 3 formats, 56/56 facts per format, plus metadata 100%. This measures the extractors on correctly classified clauses on contracts the extractors were developed against; the end-to-end figure (with the Phase 4 classifier) and labels confirmed by humans will be lower and are what the final report should quote. | Honest reporting of E4. |
| D30 | 2026-10-25 | 6 | All deterministic finding text (expected, found, reasons, category labels, template explanations) lives in `config/templates.yaml`, loaded by `get_templates()`. | HLD 0.4: no hard-coded wording in Python; reviewers can reword without code changes. |
| D31 | 2026-10-25 | 6 | Findings with the same status and severity are ordered by the reading position of their first evidence clause, then rule id (HLD 8.3 says "then location"). | Sorting the location strings would put "Page 10" before "Page 2" and mix PDF pages with DOCX sections. |
| D32 | 2026-10-25 | 6 | The embedder is optional in the engine. When MiniLM cannot be loaded, step 3's semantic search is skipped (an empty category goes straight to MISSING / NOT_APPLICABLE) and the pipeline adds a warning. | HLD 16 robustness: a failed stage gives a partial report, not a crash. |
| D33 | 2026-10-25 | 6 | Evidence and location come from the fact's `clause_ids` when it has them, else from all matched clauses. A fact whose value type does not fit the check (e.g. a string for NUMERIC_MIN) gives NEEDS_REVIEW. A saved policy's new version is always the stored version with the patch bumped, whatever version the client sent; duplicate rule ids are rejected. | Points the reviewer at the sentence that decided the status; never crash or silently pass on a bad fact or edit. |
| D34 | 2026-10-25 | 6 | E5 measured with gold clause categories and embeddings off: violation recall and precision 100% (18/18) on all 3 formats, exact status accuracy 100% (80/80 per format). Optimistic for the same reasons as D29; the end-to-end figure with the classifier is the one to quote. | Honest reporting of E5. |
| D35 | 2026-10-25 | 7 | `OllamaProvider` calls Ollama's HTTP API (`POST /api/chat`, `format` = JSON schema) with the standard library; the `ollama` extra was removed. Host is `llm.ollama_host` (new setting). | One less dependency; the HTTP API is stable and easy to mock. |
| D36 | 2026-10-25 | 7 | The `llm_cache` table is written with stdlib `sqlite3` from the core package, in the same database file the backend uses. Without a path it is in memory. | HLD 0.2 keeps the core free of web/ORM imports; the CLI still caches. |
| D37 | 2026-10-25 | 7 | Besides the HLD quote-grounding check, every number in an LLM answer (except the quote) must appear in the prompt inputs; otherwise the answer is treated like a grounding failure (one retry, then template). The executive summary gets the same check, and its prompt includes the status counts. | E7 targets 0 hallucinated values; this enforces it mechanically instead of only measuring it. |
| D38 | 2026-10-25 | 7 | Gemini uses `response_json_schema` with `response_mime_type=application/json`; a stray ```json fence is still tolerated. Retryable: 408, 429, 5xx and network errors. Untested against the live API in this environment (no API key yet). | Reliable JSON; honest note that only mocked tests ran. |
